# Размещение Pelcom на pelcom-tech.ru

Основной адрес подготовленной версии: **https://pelcom-tech.ru**, без www. Домен и DNS пока не подключены. GitHub Pages остаётся статическим промежуточным просмотром; PHP и база Битрикса на Pages не запускаются.

## Что заказать у хостера

Хостинг с поддержкой «1С-Битрикс: Управление сайтом», Linux, актуальной исправленной PHP 8.3/8.4, MySQL 8.0+, HTTPS, резервного копирования и доступом к файлам/БД (SFTP/SSH желателен). Отдельный VPS для старта не обязателен; совместимый виртуальный хостинг подходит.

Регистрация и лицензия CMS не включают услугу хостинга. При заказе хостинга указать домен **pelcom-tech.ru**. Перед переносом проверить окружение официальным bitrix_server_test.php; конкретный тариф согласовать с поддержкой хостера под «Малый бизнес».

Требования: https://www.1c-bitrix.ru/products/cms/requirements.php

## DNS в REG.RU — когда будет хостинг

Сейчас записи не меняются: IP хостинга ещё неизвестен. После размещения и проверки сайта:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | @ | IPv4 сервера, выданный хостером |
| A | www | Тот же IPv4 |

Записи редактируются там, где обслуживается активная DNS-зона домена. Если используются ns1.reg.ru/ns2.reg.ru, это личный кабинет REG.RU. Если используются DNS хостера — его панель. Не подставлять 127.0.0.1 и IP GitHub Pages.

Если приобретается хостинг REG.RU, можно подключить домен через его панель по официальной инструкции. Не менять NS без проверки существующих MX/TXT и других записей почты.

Инструкции REG.RU:
- https://help.reg.ru/support/hosting/privyazka-domena-k-hostingu/kak-privyazat-domen-k-hostingu
- https://help.reg.ru/support/dns-servery-i-nastroyka-zony/rabota-s-dns-serverami/kak-privyazat-domen-k-ip-adresu

## Подготовка публичных файлов

Настройки адресов хранятся в `bitrix/site.json`. Локальная сборка по умолчанию использует localhost и запрещает индексацию:

```sh
python3 bitrix/manage.py build
```

Подготовить отдельную боевую публичную часть:

```sh
python3 bitrix/manage.py build --mode production --out /абсолютный/путь/pelcom-production
```

Эта папка содержит наш шаблон, страницы, ресурсы и импорт. Она не содержит коммерческого ядра CMS, базы, лицензии и загруженных через админку файлов `/upload/`. Её накладывают на установленный Битрикс, а не используют как готовую самостоятельную установку. Боевой режим требует отдельного `--out`, чтобы случайно не переключить локальную версию.

Генерируются:
- canonical, OG, JSON-LD и sitemap для `https://pelcom-tech.ru`;
- robots с разрешённой индексацией публичных страниц и закрытием служебных путей;
- Apache `.htaccess` с HTTPS, адресом без www и 301 со старых HTML-адресов;
- `local/config/pelcom.php` с режимом и адресом;
- установка SERVER_NAME в Битриксе при запуске CLI-импорта с боевым конфигом.

Для nginx или TLS-прокси правила HTTPS/www и перенаправления адаптируются в конфигурации хостинга; .htaccess выполняется только Apache. Вначале настроить сертификат и корректное определение HTTPS, затем включать принудительный редирект, чтобы не получить цикл за прокси.

## Перенос на хостинг

1. Сохранить резервную копию текущей локальной БД, `/upload/` и включаемых файлов `local/content/`.
2. Установить/перенести Битрикс на хостинг, активировать действующую лицензию. Не использовать для публикации PHP dev-server.
3. Перенести базу и `/upload/` либо выполнить первоначальный импорт в пустой установленной CMS. Импорт существующие элементы не перезаписывает.
4. Загрузить публичную часть боевой сборки. Если переносится текущий контент с редакторскими изменениями, сохранить его вместо генерации старых текстов из исходных HTML.
5. Настроить подключение к БД и SERVER_NAME; при переносе свежей базы — выполнить `local/migrations/import.php` из CLI с корнем установленного сайта. Пароли и ключи остаются вне Git.
6. Подключить доставку заявок, проверить реальные полученные заявки, обязательные поля и согласие.
7. Проверить сайт на техническом адресе/через hosts, сертификат, 404, 301, изображения и все категории. На этом этапе индексацию можно оставить закрытой до переключения.
8. Направить домен на IP хостинга и проверить https://pelcom-tech.ru и https://www.pelcom-tech.ru.
9. Проверить canonical, robots/sitemap и разрешить индексацию только после завершения запуска.

Реальные адреса электронной почты `info@pelcom.ru` и другие контакты автоматически не заменялись: новый адрес ящика нужно создавать отдельно и согласовывать.

## GitHub Pages

Публикация настроена из `main`, `/`, без CNAME. `_config.yml` исключает каталог `bitrix/` и инструменты разработки из статической публикации. Не добавлять CNAME для pelcom-tech.ru, пока сайт на Битриксе не размещён на выбранном хостинге.
