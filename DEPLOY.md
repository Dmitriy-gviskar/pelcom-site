# Публикация сайта Pelcom

## Боевой хостинг

[Боевая версия Pelcom](https://pelcom-tech.ru/) работает на виртуальном хостинге REG.RU с установленной «1С-Битрикс: Управление сайтом», редакция «Малый бизнес». Подключение для публикации по SSH/SFTP — `u3556574@server234.hosting.reg.ru`. Корень сайта — `/var/www/u3556574/data/www/pelcom-tech.ru`. Учётные данные хостинга, подключение к БД и лицензионный ключ хранятся вне Git. [Инструкция REG.RU по SSH](https://help.reg.ru/support/hosting/dostupy-i-podklyucheniye-panel-upravleniya-ftp-ssh/rabota-po-ssh-na-virtualnom-hostinge)

Основной адрес задан в [bitrix/site.json](bitrix/site.json). `http://pelcom-tech.ru`, `http://www.pelcom-tech.ru` и `https://www.pelcom-tech.ru` перенаправляются на `https://pelcom-tech.ru` с кодом 301 и сохранением пути и параметров. В генерируемом Apache `.htaccess` за прокси REG.RU HTTPS определяется по `SERVER_PORT=443`. При изменении правил проверьте редиректы во всех трёх вариантах и валидность сертификата для обоих имён.

## DNS

Зона обслуживается DNS-серверами хостинга `ns1.hosting.reg.ru` и `ns2.hosting.reg.ru`. Ниже записи, сверенные с обоими серверами.

| Имя | Тип | Значение |
| --- | --- | --- |
| `@` | A | `31.31.198.19` |
| `@` | AAAA | `2a00:f940:2:2:1:1:0:234` |
| `www` | A | `31.31.198.19` |
| `www` | AAAA | `2a00:f940:2:2:1:1:0:234` |
| `@` | MX | `10 mx.yandex.net.` |

Обычная публикация файлов обходится без изменений DNS. При переносе хостинга сверяйте обе пары A/AAAA с новыми адресами и сохраняйте существующие почтовые записи DNS. MX отвечает за входящую почту, исходящую отправку заявок обеспечивает хостинг.

## Порядок публикации

1. Обновите рабочую ветку от `origin/main` и определите, какие файлы и маршруты входят в выпуск. Для изменений общего шаблона, стилей или скриптов учитывайте все страницы, которые их используют. Исходники статических страниц лежат в корне репозитория, файлы Битрикса собираются из них и дополняются из `bitrix/overlay/`. Для обычного обновления подготовьте список конкретных файлов для загрузки, включая новые ресурсы.
2. Соберите кандидат и откройте предпросмотр затронутых страниц. Для предпросмотра Битрикса используйте [локальную установку](bitrix/README.md). Если правка затрагивает включаемые тексты, сверьте их с текущими файлами `local/content/` на сервере, прежде чем публиковать. Проверьте компоновку, ссылки и затронутые сценарии на широком и узком экранах. Запустите [проверку разрешения изображений](#проверка-разрешения-изображений).
3. Перед загрузкой сохраните текущие версии заменяемых файлов для отката. Загрузите по SSH/SFTP согласованный набор в корень боевого сайта, сохраняя относительные пути. Сначала загрузите новые ресурсы, затем файлы, которые на них ссылаются. Для изменённых файлов проверяйте наличие и контрольные суммы на сервере. Правки каталога и БД выполняются отдельной операцией по [инструкции Битрикса](bitrix/README.md). Сохраняйте данные установленной CMS, редакторские правки в `local/content/` вне состава выпуска и содержимое `/upload/`.
4. Откройте затронутые страницы на боевом сайте в новой сессии браузера. Проверьте HTTP-статусы, видимые изменения и запросы к изменённым ресурсам. При замене изображения подтвердите загрузку нового файла и отсутствие запросов к старому на затронутых страницах. Если менялись шаблоны или маршруты, проверьте canonical, `/robots.txt`, `/sitemap.xml`, HTTP 301 со старых адресов и 404 по неизвестному пути. При регрессии восстановите сохранённые файлы и повторите проверку.
5. После проверки закоммитьте соответствующие опубликованной версии исходники и отправьте коммит в `origin/main`. Проверьте, что опубликованный коммит виден в удалённой ветке. Сохраните номер коммита и результат проверки страниц.

## Сборка файлов Битрикса

Из корня репозитория. Обычная локальная сборка использует локальный адрес и закрывает индексацию.

```sh
python3 bitrix/manage.py build
python3 bitrix/manage.py start
```

Для подготовки боевых файлов укажите отдельный каталог вывода.

```sh
python3 bitrix/manage.py build --mode production --out /абсолютный/путь/pelcom-production
```

Боевая сборка создаёт файлы для загрузки поверх установленного Битрикса. Она включает шаблон, страницы, ресурсы и файлы импорта, генерирует адреса для canonical, OG и JSON-LD, правила индексации и перенаправлений. Ядро CMS, база, лицензия и файлы из `/upload/` хранятся в установленном окружении. В свежем каталоге вывода `local/content/` формируется из исходных HTML, поэтому загружайте сгенерированные тексты только для страниц, которые входят в выпуск.

## Проверка разрешения изображений

Боевая сборка автоматически проверяет главную в Chromium перед записью файлов. Нужны `Pillow`, `playwright` и Chrome/Chromium. Для установки Chromium можно использовать `python3 -m playwright install chromium`. Для нестандартного пути к браузеру задайте `PELCOM_CHROMIUM`.

Перед любой загрузкой, включая точечную через SSH/SFTP, проверьте все затронутые маршруты на предпросмотре с разметкой, стилями и ресурсами кандидата. Повторяйте `--path` для каждого маршрута.

```sh
python3 bitrix/check_images.py --url http://127.0.0.1:18080 --path / --path /catalog/
```

Проверка открывает страницы при ширине 1710 и 390 CSS-пикселей и плотности 2×. Для видимых растровых `<img>` учитываются фактически загруженный файл, выбор из `srcset` и `object-fit`. При коде выхода 1 исправьте загрузку или разрешение изображения и повторите проверку перед публикацией.

В [списке исключений](bitrix/image_resolution_exceptions.json) зафиксированы существующие изображения с их адресами, SHA-256 и пределами размера на экране. При замене изображения качественным исходником удалите его исключение.

## Формы заявок

При изменениях форм или общих скриптов проверьте оба входа — форму на главной `/` и на `/contacts/`. Обязательные поля и согласие должны проходить валидацию, ссылка на согласие вести на `/consent/`, ссылка на политику — на `/privacy/`. Скрипт `/lead.js` отправляет JSON в `/local/tools/pelcom_lead.php`. Обработчик использует почтовый транспорт REG.RU для отправки на `info@pelcom-tech.ru`.

При проверке доставки отправьте помеченную тестовую заявку из каждой формы на боевом сайте и проверьте обе во входящих. Успешный ответ формы подтверждает приём заявки почтовым транспортом. Поступление в ящик проверяется отдельно.

## GitHub Pages

[GitHub Pages](https://dmitriy-gviskar.github.io/pelcom-site/) служит статическим предпросмотром из корня `main`. Настройки исключений находятся в [_config.yml](_config.yml). Пуш обновляет репозиторий и запускает статическую публикацию Pages. Боевая версия Битрикса обновляется загрузкой на REG.RU. Домен `pelcom-tech.ru` закреплён за хостингом REG.RU. В настройках Pages собственный домен отсутствует.
