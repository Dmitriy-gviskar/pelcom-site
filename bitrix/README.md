# Pelcom на 1С-Битрикс — локальный перенос

Перенесены все 134 исходные HTML-страницы: главная, 14 категорий оборудования, 99 моделей, каталог, решения по отраслям, программное обеспечение, компания, сервис, партнёры, контакты, политика и страница 404. Исходники статического сайта в корне репозитория сохранены.

## Открыть сайт

- Главная: http://127.0.0.1:18080/
- Каталог: http://127.0.0.1:18080/catalog/
- О компании: http://127.0.0.1:18080/about/
- Решения: http://127.0.0.1:18080/solutions/
- Программы: http://127.0.0.1:18080/software/
- Контакты: http://127.0.0.1:18080/contacts/
- Админка: http://127.0.0.1:18080/bitrix/admin/

Модели находятся в **Контент → Пелком → название категории**. Имя, описание, цена от, фотографии, характеристики списка и отдельные технические характеристики редактируются в инфоблоках. В каталоге информационные цены: корзина, складской учёт и оплата не подключались.

Информационные страницы и текстовые части категорий подключены через `bitrix:main.include`, файлы лежат в `local/content/` локальной установки. Для редактирования включаемого файла можно использовать режим правки или управление структурой сайта. Дизайн, скрипты и блоки сохранены из исходного сайта. Галереи-заглушки и исходные расхождения характеристик не подменялись выдуманными данными.

## Запуск и остановка

Из корня репозитория:

```sh
python3 bitrix/manage.py start
python3 bitrix/manage.py status
python3 bitrix/manage.py stop
```

Путь установки записан в игнорируемом `bitrix/.runtime-path`. Ключи и пароли — в `credentials.json` каталога окружения, вне Git. PHP и MySQL слушают только 127.0.0.1, порты 18080 и 13316. Ядро CMS, база, фотографии, загруженные в CMS, и кэш не добавляются в репозиторий.

Установлена пробная редакция «Малый бизнес» 26.150.0. Коммерческая лицензия не активировалась, платёжные данные не вводились. PHP dev-server используется только для локальной разработки.

## Как устроен перенос

- `build.py` разбирает все исходные HTML-файлы, строит маршруты, включаемые файлы, части шаблонов и манифест каталога. Зависимость: Python 3, beautifulsoup4.
- `overlay/local/templates/pelcom/` — общий шаблон с панелью администратора, метаданными и отдельными частями оформления каждой исходной страницы.
- `overlay/local/components/pelcom/kiosks/` — общий компонент всех 14 категорий; имя оставлено совместимым с первым этапом. Список и карточка получают данные из инфоблоков.
- `overlay/local/migrations/import.php` — CLI-импорт 14 категорий и 99 моделей. Повторный импорт сохраняет существующие элементы и их правки.
- `router.php` — старые адреса `.html` перенаправляются HTTP 301, неизвестные страницы получают HTTP 404. Для Apache аналогичные правила генерируются в `.htaccess`.
- `audit.py` — повторная сверка страниц, ресурсов, якорей и JSON-LD; запуск `python3 bitrix/audit.py`.
- `overlay/lead.js` — обработчик форм, отключающий ложный успех при ненастроенной доставке.
- `verify.php` — проверка всех моделей по исходным данным; если редактор намеренно изменил данные, сверка сообщит о различии.

Файлы `parts/`, `local/model_views/`, `local/migrations/catalog.json` генерируются сборкой в установленном сайте. В Git хранится генератор и собственный код, без ядра Битрикса.

## Повторная сборка

```sh
python3 bitrix/manage.py build
python3 bitrix/manage.py import
php -n -d short_open_tag=1 -d memory_limit=512M bitrix/verify.php /абсолютный/путь/к/www
```

Сборка сохраняет существующие включаемые файлы `local/content/`, чтобы не перезаписывать правки из админки. Для сознательного обновления текстовых страниц из исходных HTML используется `build.py --source ... --out ... --overwrite-content`. Сборка перегенерирует шаблоны и маршруты. Перед крупными изменениями сохранять БД и включаемые файлы.

Миграция создаёт маршруты для 99 исходных моделей. Если добавлять совершенно новые модели или менять их символьные коды, необходимо подготовить соответствующие маршруты: автоматическая генерация новых страниц из админки в этот этап не входит.

## Перед публичным запуском

Подключить действующую лицензию, обновлённый PHP на хостинге, реальную доставку заявок, домен и HTTPS. Основной домен уже задан в `site.json`: `https://pelcom-tech.ru`. Локальная сборка сохраняет localhost и закрытую индексацию. Боевую публичную часть готовить отдельно: `python3 bitrix/manage.py build --mode production --out /путь/к/публичным/файлам`. Она включает домен, sitemap, canonical/OG/JSON-LD и правила HTTPS/www для Apache. DNS не менялись; порядок подключения описан в `../DEPLOY.md`.

Формы не отправляют данные. На локальной версии убран ложный успех, включая форму партнёров: пока не настроен канал доставки, отображается ошибка. GitHub Pages и домен действующего сайта не менялись.
